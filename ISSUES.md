# Known issues

Issues discovered during automated UX testing. Each entry has enough context to fix
without reading the full conversation history.

---

## 1. --augment silently skips misspelled/missing directories

**File:** `03_train/dataset.py`, function `load_augmented` (line ~105)

**Problem:** When you pass `--augment augment_noise_0.05` to `03_train/main.py`, the
string is used as a directory name under `02_set/sets/<setname>/embeddings/<embedder>/`.
These names are auto-generated by `augment_specs.spec_dirname()` — e.g.
`NoiseSpec(prop=0.05)` → `"augment_noise_0.05"`. If the name is wrong (typo, float
formatting difference like `0.050` vs `0.05`, or simply not built yet), `load_augmented`
prints a message and silently continues with an empty result for that dir:

```python
if not os.path.isdir(dir_embed):
    print(f'DATASET: augmented embeddings not found: {aug_dirname}')
    continue
```

Training then proceeds on less data than expected, with no error and no summary of what
was actually loaded.

**Fix:** Raise a `FileNotFoundError` (or at minimum a `warnings.warn`) instead of
silently continuing. Optionally, after the loop, print a summary of how many dirs were
loaded vs skipped.

## 2. CombineSpec silently produces nothing on label mismatch

**File:** `02_set/augment.py`, function `_augment_combine_spec` (line ~139)

**Problem:** `CombineSpec(class_source='ins_buzz_Halyomorpha', class_augment='ambient_background', ...)`
matches audio files by looking for the raw label name in the pickle filename. Labels in
filenames come from the annotation pipeline — e.g. `ins_buzz_Halyomorpha.pickle` or
`ins_buzz_bee.pickle`. If `class_source` or `class_augment` don't match any filenames
(misspelling, wrong label name, label not present in this set), the function prints a
message and returns with no output file:

```python
if not frames_source:
    print(f'AUGMENT: no source frames for {spec.class_source}')
    return
```

The caller (`augment_set`) then moves on to the next spec. No error is raised. The
combine embedding file is simply never created, which is only discovered later when
training with `--augment augment_combine` loads fewer samples than expected.

**Fix:** Raise a `ValueError` instead of returning silently, or add a `--strict` flag
that makes it an error. At minimum, upgrade the print to `warnings.warn`.

To discover what raw label names exist in a set, look at the filenames under
`02_set/sets/<setname>/audio/<audio_key>/train/**/*.pickle` — the basename (minus
extension) is the label or `+`-joined multi-labels.

## 3. Per-file logging is excessively verbose

**File:** `02_set/augment.py`, functions `_augment_noisevol_spec` (line ~94) and
`_augment_combine_spec`

**Problem:** Every processed file prints a line: `AUGMENT: <relative path>`. For the
`lite` set this is ~581 lines per spec × 5 default specs = ~2900 lines per run. The
`standard` set is larger. Caching is correctly summarized (`AUGMENT: skipped N
already-done files`) but new files are printed individually with no count.

**Fix:** Replace per-file prints with a periodic counter, e.g.:
```
AUGMENT: NoiseSpec(prop=0.05) — 581 files, 7 cached
```
Or emit a dot per file and a newline at the end. If keeping per-file logging, add a
`--verbose` / `-v` flag to `augment.py`'s CLI and suppress individual lines by default.

The per-file output is in `_augment_noisevol_spec` at the line:
```python
print(f'AUGMENT: {rel}')
```

## 4. All CombineSpecs share one output directory

**File:** `02_set/augment.py`, function `_augment_combine_spec` (line ~118);
`augment_specs.py`, function `spec_dirname`

**Problem:** `spec_dirname(CombineSpec(...))` always returns `'augment_combine'`
regardless of which class pair is being combined. So all combine augmentations land in
`02_set/sets/<setname>/embeddings/<embedder>/augment_combine/train/`. When training with
`--augment augment_combine`, ALL combine pairs in that directory are loaded together —
there is no way to include one combine pair but not another.

This is fine if all combine pairs are always used together, but it becomes a problem if
you want to experiment with specific pairs (e.g. compare `buzz+rain` vs `buzz+background`
augmentation) without training separate models for each.

**Fix:** Include the class pair in the directory name, e.g.:
`augment_combine_ins_buzz_Halyomorpha+ambient_background`. Update `spec_dirname` in
`augment_specs.py`:

```python
elif isinstance(spec, CombineSpec):
    return f'augment_combine_{spec.class_source}+{spec.class_augment}'
```

**Note:** This is a breaking change — existing `augment_combine/` directories would no
longer be found by `load_augmented`. Rebuild or rename existing combine dirs if applying
this fix.
